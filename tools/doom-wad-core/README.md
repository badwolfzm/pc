# Freestanding bounded WAD directory reader (Warden D1 prerequisite)

A tiny, original, allocation-free, read-only **memory-buffer** parser for Doom IWAD/PWAD directories and lumps. The caller must obtain and authorize the input bytes via a separate reviewed Warden asset grant. This does not access files/devices and does not run the Doom engine. It complements the host-only Python WAD preflight (#74); the C core is freestanding-compatible for later Doomguest integration (#88 and D1).

`wad_open` validates header, directory and every lump's offset/length before publishing an immutable `wad_view`. `wad_lump` rechecks the requested lump bounds; `wad_find_last` resolves the last exact eight-byte name (to support replacement lumps). The borrowed bytes **must remain alive and unchanged** for the lifetime of the view. The library does not enforce immutability of caller memory or authenticate WAD contents. Zero-length lumps and repeated/overlapping offsets are allowed as in standard WADs. Upper limits: 64 MiB input and 65,536 directory entries, with 64-bit overflow-safe range checks. A WAD larger than this must be rejected or accommodated by a separately reviewed interface.

Run `make test freestanding`; optional `cc -std=c11 -O1 -g -Wall -Wextra -Werror -fsanitize=address,undefined wad.c test_wad.c -o test-sanitized && ./test-sanitized` on Linux. The `freestanding` target proves compilation to an object only, not successful linking or booting as a Warden guest. The tests use self-generated tiny fixtures and contain no copyrighted game assets.
